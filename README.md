# 通途（Tongtu）

[![CI](https://github.com/LostBeanBun/tongtu/actions/workflows/ci.yml/badge.svg)](https://github.com/LostBeanBun/tongtu/actions/workflows/ci.yml)
[![Release](https://img.shields.io/github/v/release/LostBeanBun/tongtu?label=release)](https://github.com/LostBeanBun/tongtu/releases/latest)

> 天堑变通途 —— 轻量的 Steam / GitHub 网络加速。

面向境内网络的 **Steam 社区**与 **GitHub 及其附属站点**加速工具（Windows x64，独立实现、绿色单文件）：
用「干净解析 + 双模式接管 + 无 SNI 反代」绕过 DNS 污染与 SNI 封锁。

> 📖 面向使用者的完整教程见 **[USAGE.md](USAGE.md)**。本文档偏原理与开发。
>
> ⚠️ **仅供个人学习与技术研究使用**，请勿用作其他用途。详见文末[使用范围与免责声明](#使用范围与免责声明)。

## 特性

- **本地正向代理**：白名单域名经干净 DoH 解析后直连，避免系统 DNS 被污染。
- **两种接管模式**
  - *系统代理模式*：接管浏览器等走系统代理的程序，**无需管理员权限**。
  - *Hosts 模式*：为 Steam 客户端等不走代理的程序覆盖 hosts，**需要管理员权限**。
- **无 SNI 反代（本地 MITM）**：对 SNI 被封锁的域名在本地解密，出站拨号**剥离 SNI**，靠 `Host` 头路由。
- **多来源优选 IP**：静态优选 + 远程优选（GitHub520）+ 多端点 DoH 并查。
- **启动预热**：启动后在后台把反代域名的候选竞速做完，第一个真实请求直接走快路径
  （实测 `store.steampowered.com` 冷启动首次 3.4 s → 预热后 0.89 s）。
- **不替你猜「为什么没生效」**：反代没启用会把原因（如「缺根证书，执行 `tongtu cert install` 后重启」）
  写进启动摘要、`tongtu status` 与窗口状态条，而不是只躺在日志里；窗口里的 `自检` 与 `待办`
  进一步把「发现问题 → 解决它」放进同一个入口。
- **不用命令行也能配好**：装根证书、跑自检、开自启、看「还差什么」、打开/复制/清空日志，
  全在窗口和托盘里点得动（0.2.0 的主线）。
- **能加速自己的站点**：`config.yaml` 里加一行 `custom.domains`（或 `mitm_domains`）**保存即生效**，
  不用重启；通配写法也支持（`*.example.com`，走系统代理模式）。写错了会直接告诉你哪条不对。
  窗口里的 `站点` 面板也能直接添加 / 删除 / 单独开关反代，不必手改文件。
- **一键暂停 / 定时恢复**：临时不想让通途接管网络时，点窗口的 `暂停`（或托盘「暂停全部加速」），
  系统代理、hosts、反代一次全撤掉，进程继续待命；可选 15 分钟 / 30 分钟 / 1 小时 / 2 小时
  到点自动恢复，也可以点 `恢复` 提前开回来。
- **与别的代理工具并存不乱改**：系统代理被 Clash / v2rayN 之类改写时会如实报成
  「已被其他程序接管」，退出时**不覆盖对方的设置**；`listen` / `control` 端口被占用时自动改用空闲端口，
  不会因为端口冲突就起不来。
- **开机自启**：HKCU Run 键（无需管理员）或最高权限计划任务，`--hidden` 不显示界面窗口。
- **零参数即开**：双击 exe（或不带子命令运行）就等同于 `start`，显示自己的窗口（点 × 只隐藏）。
- **双击不出现 cmd 窗口**：exe 以图形子系统编译，双击时 Windows 根本不会创建控制台窗口；
  从终端启动则照常在终端里看到日志，界面就绪后进程主动脱离控制台，**关掉那个终端窗口不会结束通途**。
- **异常退出不留错配置**：接管系统代理 / hosts 期间会拉起一个同名「监护进程」，
  主进程一旦崩溃或被强杀，它立刻把系统代理与 hosts 还原成原来的样子；注销 / 关机由窗口消息触发还原
  （进程被强杀来不及还原时，下次启动也会自动清理遗留状态）。
- **断电之后也能自愈**：接管期间在 `HKCU\...\RunOnce` 登记一次性的 `TongtuRecover`，
  监护进程每 1.5 秒巡检补写；下次登录时先把上一轮残留的系统代理 / hosts / 锁文件收干净，
  然后自己撤掉——只兜底一次，不留常驻项。断电、蓝屏、长按电源键都属于这一类。
- **假活自愈**：进程还在、界面还显示「运行中」但网络已经不通时（监听丢了、hosts 托管块被改写、
  所有 DoH 端点失败），健康检查会自动重绑监听、重写 hosts、重置 DNS 缓存并重新预热；
  系统代理若已被别的程序接管，只标记「降级」并说明原因，**不抢回、不覆盖**。
- **睡眠 / 换网自动恢复**：从睡眠唤醒、换 Wi-Fi、插网线、开关 VPN 后，自动作废旧网络的 DNS 与
  优选 IP 缓存、关闭空闲连接、按需重写 hosts 与重绑本地 `:443`；恢复动作串行化并防抖，
  同一次事件只执行一遍。
- **检查更新（只查不下载）**：托盘「检查更新」或 `tongtu version --check` 查 GitHub Releases；
  有新版本就问一句，点是打开 Release 页面。绿色单文件不做自动替换——在 Windows 上替换
  正在运行的 exe 不可靠，悄悄失败比不升级更糟。
- **CLI + 系统托盘**：托盘右键菜单承载全部可配置项，点一下即开/关并写回配置。
- **常规窗口界面**：标准的系统标题栏（跟随深浅色）+ 不透明窗口底 + 自绘状态条
  （状态点 + 文字 + 一条与卡片对齐的发丝分隔线）+ 圆角日志卡片与发丝描边；
  按显示器 DPI 渲染，窗口位置与大小记忆到下次启动。菜单（托盘右键、窗口右键）也跟随系统主题。
  配色按「深浅同色相只差明度 / 一个颜色只干一件事 / 对比度达 WCAG」三条规矩校准，
  状态词还会按健康度变色（运行中 · 部分生效 · 已停止）。

## 加速原理（A + B + C）

### A．干净解析 + 双模式接管

系统 DNS 对受污染域名会返回假 IP（例如把 `steamcommunity.com` 解析到 Facebook 的地址）。本工具改用 **DoH（DNS over HTTPS）** 并查多个端点，并把结果作为直连候选：

- **系统代理模式**：本地代理接到 `CONNECT host:443` 后，用干净 IP 直连（不走系统 DNS）。
- **Hosts 模式**：把白名单域名写入 hosts；受 SNI 封锁的域名指向本机回环（`127.0.0.1` **与 `::1`**），
  由本地监听接管——只写 `127.0.0.1` 时，域名自己的 AAAA 记录仍然生效，而客户端（Happy Eyeballs）**优先 IPv6**，
  于是它连的是真实 IPv6 边缘，既不经过本地接管、还可能正好撞上 SNI 封锁。本地 `[::1]` 监听绑不上时不会写 `::1`。

### B．无 SNI 反代（MITM）

GFW 会对特定域名做 **SNI 阻断**：同一 IP 换 SNI 即被 RST。既然 ClientHello 里的 SNI 是触发点，工具就：

1. 本地自签 CA 为白名单域名签发证书，对客户端**本地解密**（仅在 HTTPS 上）；
2. 出站时 `tls.Config{ServerName: ""}`，**ClientHello 不携带 SNI**；
3. 用原始 `Host` 头让上游按域名路由。

仅对配置 `mitm.domains` 列出的域名解密，**其余流量端到端隧道、不解密**。

默认反代域名：`*.steamcommunity.com`、`store.steampowered.com`、`avatars.steamstatic.com`、
`raw.githubusercontent.com`、`gist.github.com`、`github.com`。

> 名单是按实测结果定的，只收「真 SNI 被阻断、剥离 SNI 后按 Host 头仍能正常响应」的域名：
> - `store.steampowered.com` 真 SNI 直连会超时、或只收到十几 KB 就断流，反代后实测 **200**；
> - `avatars.steamstatic.com`（Steam 头像）直连被 RST，反代后正常；
> - `api.steampowered.com`、`cdn.steamstatic.com`、`login.steampowered.com`、`checkout.steampowered.com`
>   等未封锁 SNI，**保持隧道**，更快也更稳。
>
> ⚠️ 不要图省事写 `*.steampowered.com`：`login.steampowered.com` 剥离 SNI 后握手会**直接失败**
> （实测 `tls: internal error`），登录页会被一起弄坏。要加域名请逐个确认。
>
> 另外，`www` / `help.steamcommunity.com` 的干净 DoH 答案会落在不可达的机房（TCP:443 全超时），
> 因此 `dns.static_hosts` 里给了实测可用的兜底 IP；没有它就只有「竞速全部失败 → 十几秒后 502」。

### C．启动预热

反代的第一次访问要现查干净 DoH、再对多个候选 IP 逐个做 TCP + 无 SNI TLS 探测（冷状态 2–5 秒）。
启动后通途会在后台对 hosts 名单与反代域名做一遍**同样的**探测，命中的结果写进与真实请求
**共用**的优选缓存——于是你点开商店时直接走快路径。实测 `store.steampowered.com`：

| | 首次访问耗时 |
|---|---|
| 冷启动（预热前） | 3.4 s |
| 预热后 | 0.89 s |

预热是尽力而为，失败只记日志、不影响服务。

反代与 HTTP 转发路径还会删掉上游的 `Alt-Svc` 响应头：hosts 模式下反代域名指向本机回环（`127.0.0.1` 与 `::1`），
而本地只监听 TCP，留着它只会让浏览器去试注定失败的 QUIC（UDP:443），白等几秒。

## 环境要求

- Windows 10/11 x64
- 构建需 Go 1.21+；运行只需 `tongtu.exe`

## 构建

**推荐**：使用自带脚本（自动设置工具链与代理，注入版本号）：

```powershell
.\build.ps1                 # 生成 dist\tongtu.exe（版本号自动读取 VERSION）
.\build.ps1 -Version 0.0.9  # 临时指定版本号（不改 VERSION 文件）
```

或手动（**注意 `-H windowsgui`**：没有它就会编译成控制台程序，双击时会出现一个 cmd 窗口）：

```powershell
$env:PATH = "$env:LOCALAPPDATA\Programs\Go\bin;$env:PATH"
$env:GOPROXY = "https://goproxy.cn,direct"
go build -trimpath -ldflags "-s -w -H windowsgui -X main.Version=$(Get-Content VERSION -Raw).Trim()" -o dist\tongtu.exe .\cmd\tongtu
```

测试（跨平台可跑：Windows 专属部分用 `_windows.go` / `_other.go` 成对桩隔离，因此 Linux CI 也能 `go vet` 与编译）：

```powershell
go test ./...
go vet ./...
```

界面部分不只是「能编译」：状态条与卡片会**画到内存 DC 上逐像素断言**（状态点颜色、卡片底色与
圆角、发丝线所在行、内边距、文字色系），配色则按 WCAG 对比度与色相一致性校验，
日志的排版与分级配色走纯逻辑单测（`logview_test.go`），日志控件的实际颜色则用
`EM_GETCHARFORMAT` 直接读回断言（深浅两套配色都验）——
参见 `cmd/tongtu/palette_windows_test.go`、`window_windows_test.go`、`logview_test.go`。

### 图标与清单资源

`cmd/tongtu/rsrc_windows_amd64.syso` 是编译进 exe 的 Windows 资源段：图标（资源管理器 / 任务栏 /
Alt+Tab 里显示的那个）与应用程序清单（`cmd/tongtu/tongtu.manifest`，请求 comctl32 v6）。
图标由 `internal/icon/icon.ico` 生成，已随仓库提供，**平时构建不需要任何额外工具**。

改了图标或清单后按下面两步重新生成（`rsrc` 只在重新生成时需要）：

```powershell
go run ./tools/genicon internal/icon/icon.ico      # 重绘 ICO（16/32/48 三档）
go install github.com/akavel/rsrc@latest           # 只需一次，安装资源编译器
rsrc -arch amd64 -ico internal/icon/icon.ico -manifest cmd/tongtu/tongtu.manifest -o cmd/tongtu/rsrc_windows_amd64.syso
```

## 版本与变更记录

版本号遵循[语义化版本](https://semver.org/lang/zh-CN/)，唯一的权威来源是仓库根目录的
[`VERSION`](VERSION)：

```powershell
.\bump.ps1 patch   # 修 bug、小改动       0.0.1 -> 0.0.2
.\bump.ps1 minor   # 新增功能、行为有变化  0.0.2 -> 0.1.0
.\bump.ps1 major   # 达到可发布状态       0.4.0 -> 1.0.0
```

`bump.ps1` 会同时改写 `VERSION` 与 `cmd/tongtu/version.go`（`version_test.go` 保证两者不漂移），
`build.ps1` 自动读取 `VERSION` 并把版本号写进 exe（`tongtu version` 可见）。
每个版本的改动记在 [CHANGELOG.md](CHANGELOG.md)；`0.0.x` 属开发期，配置与命令行为都可能变，
到 `1.0.0` 才承诺向后兼容。

### 发布与升级

重要版本会打 `vX.Y.Z` tag，推上去后由 [`.github/workflows/release.yml`](.github/workflows/release.yml)
自动完成：跑质量门 → 构建 Windows x64 单文件 → 生成 `SHA256SUMS.txt` 与发布说明 → 发布 GitHub Release。
CI（[`ci.yml`](.github/workflows/ci.yml)）在每次 push / PR 时跑 gofmt、vet、staticcheck、跨平台编译与测试。

升级方式（绿色单文件，没有安装器）：

1. 托盘右键「检查更新」，或执行 `tongtu version --check`；有新版本时打开 Release 页面。
2. 下载 `tongtu-X.Y.Z-windows-x64.exe`，用 `SHA256SUMS.txt` 校验：

   ```powershell
   Get-FileHash .\tongtu-X.Y.Z-windows-x64.exe -Algorithm SHA256
   ```

3. 退出通途（托盘右键「退出」或 `tongtu stop`），用新 exe 覆盖旧的，再启动。
   `%APPDATA%\tongtu` 里的配置、证书与日志都会保留；配置版本升级时会先备份、再保留你的设置升级。

> 不做「自动下载替换」：在 Windows 上替换正在运行的 exe 不可靠，静默失败比不升级更糟。

## 快速开始

### 系统代理模式（推荐，无需管理员）

```powershell
dist\tongtu.exe start            # 默认同时尝试接管系统代理与 hosts
# 仅接管系统代理（不动 hosts）：
dist\tongtu.exe start --no-hosts
```

首次启动会提示安装本地根证书（无 SNI 反代所需，安装到**当前用户** Root 存储，无需管理员）。
也可不反代直接跑：`--no-mitm`。

查看状态 / 停止：

```powershell
dist\tongtu.exe status
dist\tongtu.exe stop             # 还原系统代理与 hosts
```

### Hosts 模式（需要管理员）

以**管理员**身份：

```powershell
dist\tongtu.exe start --no-sysproxy   # 只接管 hosts
```

仅当以管理员运行时 hosts 才会写入；否则会打印告警并降级（系统代理模式仍可用）。

### 验证效果

```powershell
dist\tongtu.exe test steamcommunity.com github.com
```

## 命令参考

| 命令 | 说明 |
|---|---|
| `tongtu`（不带参数） | 等同 `tongtu start`——双击 exe 即为此 |
| `tongtu start` | 启动服务（`--no-sysproxy` / `--no-hosts` / `--no-mitm` / `--no-tray` / `--hidden`） |
| `tongtu stop` | 停止服务并还原系统代理与 hosts |
| `tongtu status` | 查看运行状态（`--json` 输出原始 JSON） |
| `tongtu test [域名...]` | 测试干净解析、TCP 连通性与经代理的 HTTPS 访问 |
| `tongtu cert install` | 生成（如不存在）并安装本地根证书 |
| `tongtu cert status` | 查看证书状态 |
| `tongtu cert uninstall` | 移除本地根证书（幂等） |
| `tongtu autostart on` | 开启开机自启（默认：当前用户；`--elevated` 则用最高权限计划任务） |
| `tongtu autostart off` | 关闭开机自启 |
| `tongtu autostart status` | 查看开机自启状态 |
| `tongtu version` | 显示版本号（`--check` 联网检查是否有新版本，只查不下载） |

全局标志：`--config <路径>`（默认 `%APPDATA%\tongtu\config.yaml`）。
`--no-tray` / `--no-sysproxy` / `--no-hosts` / `--no-mitm` / `--hidden` 挂在根命令上，
所以 `tongtu --no-hosts` 与 `tongtu start --no-hosts` 等价。

### 系统托盘

不带参数运行（或双击 exe）后，托盘右键菜单承载**全部可配置项**，点一下即开/关，
改动立即生效并写回 `config.yaml`：

```
通途 网络加速
────────────────
暂停全部加速
暂停定时              ▸
────────────────
系统代理模式          [✓]
Hosts 模式            [✓]
无 SNI 反代            [✓]
────────────────
加速 Steam            [✓]
加速 GitHub           [✓]
────────────────
开机自启              [✓]
开机自启（最高权限）    [ ]
────────────────
以管理员身份重启
────────────────
显示/隐藏窗口
复制代理地址
检查更新
打开配置文件
打开配置目录
────────────────
退出
```

- 最上面的「暂停全部加速」在暂停后变成「恢复全部加速」：撤掉系统代理、hosts 与反代，
  进程继续运行；恢复时按**当前配置**原样开回来（不会重新猜你想开哪几项）。
- 「暂停定时」子菜单提供 15 分钟 / 30 分钟 / 1 小时 / 2 小时四档，到点自动恢复；
  剩余时间写在托盘悬停提示里（`已暂停（12 分钟后自动恢复）`），也可以随时点
  「恢复全部加速」提前恢复。
- 菜单中的勾选状态每 3 秒与运行时同步（也能反映控制 API 的改动与启动时的接管失败）。
- **鼠标悬停在托盘图标上**就能看到实时状态与流量，不用打开窗口：
  `通途 Tongtu · 运行中（已运行 1 小时 23 分）· 系统代理✓ · Hosts✗ · 反代✓ · ↓1.2M ↑340K`
  （体积用紧凑写法，提示行只有一行宽）。暂停时状态词写「已暂停」。
- 「开机自启（最高权限）」需要计划任务权限；非管理员运行时该项为灰色不可点。
- **「以管理员身份重启」**（非管理员时可点）：先弹窗确认 → 还原系统代理与 hosts 并退出当前实例 →
  释放控制端口后再弹 UAC 拉起提权实例。顺序是刻意安排的：先退出再提权，新实例才不会撞上
  「tongtu 已在运行」；若在 UAC 里点了取消，只是本次重启作罢（不弹错误框），需要时手动再启动一次。
- **「检查更新」只查不下载**：联网查 GitHub Releases，结果用弹框告诉你（已是最新 / 发现 vX.Y.Z）；
  有新版本时点「是」打开 Release 页面，由你自己下载。查询失败会说清是网络问题还是仓库还没有发布版本。
- 所有菜单操作失败都会弹出提示框（开机自启没有界面时同样可见）。
- **双击 exe 启动后显示的是通途自己的窗口**（承载启动信息与运行日志，不是黑底控制台），
  **双击时不会出现 cmd 窗口**：exe 以图形子系统编译。**点窗口的 × 只是隐藏窗口**，
  服务与托盘继续运行。想再看日志：左键点托盘图标，或托盘右键 →「显示/隐藏窗口」。
  （控制台窗口做不到「只关窗口」：Windows 在控制台窗口被关闭时会直接结束该进程，
  `CTRL_CLOSE_EVENT` 拦不住；所以双击启动改用自绘窗口。）
- **退出**只能走托盘右键「退出」或 `tongtu stop`。
- **从终端启动**（`tongtu` 或 `tongtu start`）：日志先打在终端里；界面与托盘就绪后进程会
  **主动脱离控制台**，此后**关闭该终端窗口不再影响通途**（终端里也不再收到 `Ctrl+C`，
  请用托盘「退出」或 `tongtu stop`）。`--no-tray` 时刻意保留终端作为唯一界面。

### 通途窗口（界面）

双击 exe 后显示的就是这个窗口，从上到下是三部分：状态条两行 + 日志卡片（工具条 + 日志区）。

```
┌───────────────────────────────────────────────────────────────────────────┐
│  ▣  通途 Tongtu 0.7.0  运行中          ● 系统代理   ○ Hosts   ● 无SNI反代 │
│  服务组 steam、github · 活跃隧道 2 · ↓1.2 MB ↑34 KB · 已运行 1 小时 23 分 │
│                待办 1  暂停  自检  服务组  站点  打开配置  日志  退出     │
├───────────────────────────────────────────────────────────────────────────┤
│  ⌕ 过滤日志…                只看警告                                       │
│  15:07:02  信息  已启用系统代理模式                                        │
│  15:07:03  警告  写入 hosts 需要管理员权限                                 │
│                · err=Access is denied.                                    │
└───────────────────────────────────────────────────────────────────────────┘
```

点第二行的 `站点`，卡片区切换成自定义站点面板（再点一次回到日志）：

```
┌───────────────────────────────────────────────────────────────────────────┐
│  [ huggingface.co                      ]  添加                            │
│  ─────────────────────────────────────────────────────────────────────    │
│  huggingface.co                              ● 反代   删除                │
│  *.example.com                               ○ 反代   删除                │
│  ─────────────────────────────────────────────────────────────────────    │
│  添加后立即生效；支持 *.example.com 通配，粘贴完整网址也可以。             │
└───────────────────────────────────────────────────────────────────────────┘
```

- **两行状态条**：第一行是「小图标 + 标题 + 状态词（左）」与「三个开关胶囊（右，右对齐）」，
  第二行是「服务组 / 活跃隧道 / 上下行流量 / 运行时长（左）」与「动作按钮（右）」。窗口变窄时按段降级
  （先丢运行时长、再丢流量与隧道数，服务组尽量留住），再窄就丢掉工具条里的过滤框，
  最后才压缩标题——状态词与开关始终完整，它们是「一眼看清」的核心。
- **开关胶囊可以直接点**：点 `系统代理` / `Hosts` / `无SNI反代` 立即切换。切换在后台执行
  （hosts 接管要拉远程 hosts 源、反代要重新预热，慢的时候有好几秒），状态条先显示「正在切换…」，
  做完换成结果（约 3 秒后自动消失）；失败则把原因显示在同一位置**并**写进日志——不弹模态框、
  不打断你正在看的日志，窗口也不会卡住。切换期间再点开关不会重复触发。切换只改被点的那一项
  （另一项的实际状态会一并带上，见 `SetMode`）。
- **悬停有反馈**：可点的控件在常态下不铺底色（幽灵控件），鼠标移上去才浮出一层淡淡的底色，
  光标变成手型，并弹出系统提示条说明它是干什么的（例如「Hosts 模式：覆盖 hosts 解析，
  供 Steam 客户端等不走代理的程序使用（需管理员）。点击开关」）。
- **待办：把「还差点什么」变成可以点的按钮**：不满足前提条件时，动作区最左侧出现 `待办 N`，
  点开是本机确实没配好的事（装证书 / 以管理员身份重启 / 开机自启 / 系统代理被抢），
  每条都带一句为什么，点一下就处理并在原位重算。没待办时这个按钮根本不出现。
- **自检**：`自检` 直接在当前窗口跑一次完整体检（干净解析 + 直连 + 经代理），
  结果成块写进日志卡片、结论显示在状态条；和 `tongtu test` 是同一份逻辑。
- **一键暂停 / 定时恢复**：动作区最左侧的 `暂停` 把系统代理、hosts 与反代一次全撤掉，状态词变「已暂停」，
  进程与窗口继续运行；点它先选时长（15 分钟 / 30 分钟 / 1 小时 / 2 小时 / 直到手动恢复），
  到点由 app 层自动恢复，窗口隐藏、只剩托盘也照常到期。剩余时间显示在状态条第二行
  （「暂停中，12 分钟后自动恢复」）。暂停后按钮变成 `恢复`，点一下按当前配置原样开回来；
  暂停期间不会再有「重新接管系统代理」之类的待办打扰你。
- **自定义站点面板**：点 `站点` 把卡片区切换成站点列表（再点一次回到日志）。输入框接受域名，
  也可以直接粘贴完整网址（自动去掉协议 / 路径 / 端口）；点「添加」后立即重建白名单并写回配置，
  hosts 与反代当场跟上。每行可单独开关 `反代`（该域名同时走无 SNI 反代，需已安装根证书）或 `删除`。
  输入为空时「添加」只是弱化显示，点了会说明原因而不是静默失败。增删与切换都在后台执行，
  窗口不会卡住；列表放不下时只画能放下的行（不做滚动）。
- **动作按钮**：第二行右侧是 `待办 N`（有问题才出现）、`暂停 / 恢复`、`自检`、`服务组 ▾`（勾选式菜单，
  和托盘菜单同一套开关）、`站点`、`打开配置`（用记事本打开 `config.yaml`）、`日志 ▾`、`退出`
  （停止加速并还原系统代理与 hosts，等同于托盘右键「退出」；点窗口的 × 只是隐藏窗口）。
- **日志菜单**：`日志 ▾` 里是「打开日志文件」「复制诊断信息」「清空窗口日志」。
  诊断信息带版本、配置要点、服务组、端口、证书与自启状态，粘贴给别人就能定位问题；
  日志默认就落盘（见下文 `log.file`），不需要先改配置。
- **日志过滤**：卡片顶部有过滤框与「只看警告」开关。关键字不区分大小写、按整行匹配，
  续行（`· ` 开头的属性行）跟着正文行走，不会把一条记录拦腰截断；没有命中时显示一行提示
  而不是一片空白。输入做了 180ms 防抖，连续打字只在停手后重排一次。
- **日志分级配色**（`cmd/tongtu/logview.go` 是显示层，独立于文件日志）：时间戳用弱化色，
  级别词固定两个汉字（`调试` / `信息` / `警告` / `错误`）并按语义上色（错误红、警告橙、其余中性），
  正文用一级文字色，`k=v` 属性用次要色；一行太长时属性缩进换行（续行以 `· ` 开头），
  避免日志挤成一片。着色靠系统自带的 `msftedit.dll`（`RICHEDIT50W`），
  取不到时自动退回普通文本控件——功能不变，只是没有颜色。
  文件日志与控制台仍是结构化文本（`time=… level=… msg=… k=v`），诊断时用得上。
- **常规窗口样式**：用系统标准的标题栏（跟随深浅色），客户区由我们自己铺**不透明**主题底色，
  里面放一张圆角日志卡片（圆角底色 + 外围一圈 1 像素发丝描边，日志控件再内缩一圈留出内边距，
  文字与滚动条都不贴边）；状态条是**自绘**的（状态点 + 文字，下方一条与卡片对齐的发丝分隔线）。
  圆角交给系统默认处理，不额外做特效。
- **为什么没有「液态玻璃」/系统材质**（真机实测，Windows 11 24H2 + GDI 自绘，留档避免以后又试一遍）：
  `DwmExtendFrameIntoClientArea(-1)` 会把整块客户区变成 DWM 的「玻璃」，GDI 画上去的像素会被
  按材质的不透明度重新合成——实色被冲淡到 60%~80%，深色主题下浅色文字直接糊到看不见；
  壁纸偏亮时材质本身还会发白（整个窗口蒙一层白纱）。只设 `DWMWA_SYSTEMBACKDROP_TYPE`（云母）
  不伸框虽然客户区安全，但省下的只是一层标题栏磨砂；未公开的 `SetWindowCompositionAttribute`
  （亚克力）在新版 Windows 上返回成功却不生效，同样会冲淡客户区。GDI 自绘的窗口就老老实实
  用系统默认外观：配色才落得准、文字才够清楚。
- **系统绘制的部分也用现代外观**（`cmd/tongtu/tongtu.manifest`，由 `rsrc` 编译进 exe 资源段）：
  清单里请求 comctl32 v6，于是过滤框的「空内容提示」（`EM_SETCUEBANNER`）、悬停提示条、
  右键菜单与滚动条都是当前 Windows 的外观，而不是 v5 的旧样式。这份清单是必需的——
  v5 不支持 `EM_SETCUEBANNER`，没有它过滤框会是一个没有任何说明的灰框。
- **配色的三条规矩**（把「好看」变成可度量的规则，回归测试见 `cmd/tongtu/palette_windows_test.go`）：
  1. **深浅同色相、只差明度**：中性色统一为冷灰（H≈240°），语义色深浅两套共用色相——
     浅色压深一档（压在亮底上够黑），深色用「提升层」变体（压在暗底上够亮）。切换主题像
     同一套设计的两种明度，而不是两种风格。
  2. **一个颜色只干一件事**：状态点只表「开关状态」（**绿 = 开，灰 = 关**），文字只用文字色阶
     （正文 / 次要 / 弱化三级），强调色只给标题。不再出现「整行彩色文字」这类配色噪音。
  3. **对比度按 WCAG 校准**：正文 ≥7:1、次要文字 ≥4.5:1、弱化文字与状态点 ≥3.5:1；
     测试会逐个色对算对比度，改坏一个色值就会红。
- **状态词也是状态位**：标题后面那个词跟着健康度变色——`运行中`（绿）、`部分生效`（橙，例如
  非管理员下 hosts 接管失败）、`已停止`（灰）。颜色只是强化，词本身写明了状态，不依赖颜色单通道。
- **顶部状态条**：每 3 秒刷新一次，一眼看清三个开关、当前服务组、活跃隧道数与上下行流量
  （和托盘菜单里的勾选一致）。
- **改变窗口大小不会打乱阅读位置**：停在末尾的继续跟随最新（像 `tail -f`），往上翻看的留在原处
  ——日志控件在缩放后会把视图重置，因此布局时会把它补回来。
- **深浅色主题**：跟随 Windows 的「应用模式」（设置 → 个性化 → 颜色）；深色下标题栏、滚动条
  以及**系统绘制的菜单**（托盘右键、窗口右键）都会一起变深。运行中切换主题会当场生效（无需重启），
  界面切换时复用的是同一批 GDI 对象，因此反复切换也不会泄漏资源。
- **高分屏清晰**：进程声明为 per-monitor DPI 感知，窗口在不同缩放的显示器之间拖动会自动换字体与布局；
  发丝线保持 1 物理像素（高 DPI 下更精致），状态点与圆角则随 DPI 放大。
- **能被截屏工具正确抓取**：自绘窗口同时实现 `WM_PRINTCLIENT`，因此 PrintWindow / 共享软件 /
  录屏工具抓到的是完整画面（状态条 + 日志卡片描边俱在），而不是一片空白。
- **日志区操作**：`Ctrl+A` 全选、`Ctrl+C` 复制；右键有「复制 / 全选 / 复制代理地址 / 打开配置文件 / 清空窗口日志」。
  - 正在**划选文本**时，新日志不会打断你的选区；
  - 正在**往上翻看历史**时，新日志不会把视图拽回末尾；停在末尾时则自动跟随（像 `tail -f`）。
- **窗口位置与大小**会记住，存放在 `%APPDATA%\tongtu\window.json`（删掉即恢复默认 860×520）；
  窗口最小 620×320——再小的话状态条两行与卡片工具条就挤不下了。
- 任务栏与资源管理器里 `tongtu.exe` 显示的是通途自己的图标（帆船），不再是系统默认图标。

### 开机自启

```powershell
tongtu autostart on              # 无需管理员：写入 HKCU Run 键，登录时以当前用户启动（系统代理模式）
tongtu autostart on --elevated   # 需管理员：创建「最高权限」计划任务，登录时以管理员启动（hosts 模式亦可用，无 UAC 弹窗）
tongtu autostart off
tongtu autostart status
```

- 自启命令为 `tongtu.exe start --hidden`（不显示界面窗口，只保留托盘图标）。
- `--hidden` 仍会创建一个**不可见的窗口**：注销 / 关机时系统通过它（`WM_QUERYENDSESSION`）
  通知通途先还原系统代理与 hosts，避免「关机时留下指向本地代理的注册表项」。
- 两种机制互斥：开启一种会自动移除另一种，避免重复启动。
- 若要在开机后自动为 **Steam 客户端**（需要 hosts 模式）加速，请以管理员身份执行 `tongtu autostart on --elevated`。
- `--hidden` 模式下首次运行**不会**弹出根证书安装提示；如需无 SNI 反代，请先手动执行一次 `tongtu cert install`。

## 配置说明

`%APPDATA%\tongtu\config.yaml`（带版本号，升级时先备份为 `config.yaml.vN.bak`，再保留用户设置升级）：

version: 4
listen: 127.0.0.1:19180        # 本地代理监听（被占用时自动改用空闲端口）
control: 127.0.0.1:19181       # 控制 API（仅回环；被别的程序占用时自动换口并写回本文件）

    - https://doh.pub/dns-query

    - https://1.1.1.1/dns-query
    - https://8.8.8.8/dns-query
  timeout_sec: 5
  cache_min_sec: 60
  cache_max_sec: 600
  remote_hosts:                # 远程优选 IP 列表（hosts 格式）
    - https://raw.hellogithub.com/hosts
  static_hosts:                # 静态优选 IP，优先级最高
    gist.github.com:          [140.82.112.3, 140.82.113.3, 140.82.114.3]
    github.com:               [140.82.112.3, 140.82.113.3, 140.82.114.3]

    www.steamcommunity.com:   [104.89.103.51, 184.30.89.225]
    help.steamcommunity.com:  [104.89.103.51, 184.30.89.225]
mitm:
  enabled: true
  auto_cert: true              # 首次启动提示安装本地根证书
  domains:                     # 需要本地解密的域名（支持 "*.example.com"）
    - '*.steamcommunity.com'
    - store.steampowered.com   # 真 SNI 直连被阻断
    - avatars.steamstatic.com  # 头像：直连 RST
    - raw.githubusercontent.com

    - github.com

> 界面窗口（通途自己的窗口）里**始终**能看到日志，与控制台、文件互不影响；
> 想关掉文件日志就把 `file` 设成 `off` / `none` / `-`。

> `custom` 里的规则会在加载时规范化（转小写、去空白、去重），写错（带协议 / 端口 / 路径、
> 通配位置不对）会直接报错说明哪一条不对。**改完保存即生效**：进程每 2 秒看一次配置文件，
> 变了就把「服务组 / 自定义站点 / 反代域名」重新应用一遍并写一条「配置已热生效」；
> 端口、DNS 端点、日志级别这类要重建组件的字段仍需重启。

> 新增的内置默认 `dns.static_hosts` 与 `mitm.domains` 会在加载时**合并**进已有配置（保留你的自定义项）。

## 系统状态的接管与还原

tongtu 会临时修改**系统代理**与 **hosts**，因此会尽最大努力保证"停下来就干净"——
**无论进程怎么退出，都不会留下指向已停止代理的错误配置**：

| 退出方式 | 谁来还原 | 时机 |
|---|---|---|
| `tongtu stop` / 托盘「退出」 | 主进程自己 | 立即 |
| `Ctrl+C`（终端启动时） | 主进程自己 | 立即 |
| 点窗口的 × / Alt+F4 | **不退出程序**，只隐藏窗口 | — |
| 关闭启动它的终端窗口 | 界面就绪后进程已脱离控制台，**不受影响** | — |
| **注销 / 关机** | 窗口收到 `WM_QUERYENDSESSION` → 主流程还原（最多等 4 秒）后才放行结束会话 | 会话结束前 |
| **崩溃 / 被任务管理器强杀** | **监护进程**（同名 exe 的隐藏子进程）等到主进程退出后立即还原 | 毫秒级 |
| 断电 / 蓝屏 / 直接拔电 | 无法执行任何代码；接管期间登记的 `RunOnce` 自愈项会在**下次登录**时清理一次并自撤 | 下次登录或下次 `start` / `stop` |

细节：

- **监护进程**：一旦接管了系统代理或 hosts，主进程就拉起 `tongtu.exe __guard --guard-pid <pid> --guard-token <token>`。
  它只做一件事——等待主进程句柄进入已通知状态，然后调用与「下次启动」相同的清理逻辑。
  清理是**幂等**的：如果主进程已经优雅还原过，它就是空操作（不会误动新实例的状态）。
- **令牌防误清**：`%APPDATA%\tongtu\guard.json` 记录「当前这轮接管」的令牌。新实例启动时会先改写令牌，
  于是上一轮残留的监护进程会发现"已经换人"而选择什么都不做。优雅退出时主进程会**回收自己的令牌**
  （比对 PID + 令牌，因此绝不会删掉刚启动的新实例写下的令牌）；若上一轮连令牌都没来得及回收
  （监护进程被一起带走），下次启动会识别出"主人已经不在了"并顺手回收、记进 `guard.log`。
- **监护进程也可能被限制**：某些启动方式（IDE、CI、任务计划、被作业对象包住的终端）下，
  子进程无法脱离作业对象，会随主进程一起被结束——此时崩溃防护实际失效。通途检测到这种情况会在
  日志里告警，并在启动摘要里显示「崩溃防护：受限（…异常退出要等下次启动才还原）」，不会让人误以为万无一失。
- **断电自愈（RunOnce）**：监护进程还活着才能兜住崩溃；连机器都断电了就没人执行清理。
  为此接管系统期间会在 `HKCU\Software\Microsoft\Windows\CurrentVersion\RunOnce` 登记
  `TongtuRecover = "<exe>" __recover`（当前用户权限，不需要管理员），监护进程每 1.5 秒巡检一次，
  被别的清理软件删掉就补回来（值相同不写注册表）。下次登录时 Windows 执行它：
  清理上一轮残留的系统代理 / hosts / `guard.json`，然后**自己删掉 RunOnce**，只兜底一次。
  暂停、手动关掉接管、正常退出、监护进程完成还原后都会立即撤销这一项。
  `__recover` 是幂等的——发现还有活着的持有者（例如只是界面崩了、服务仍在跑）就什么都不做。
  - 已知边界：如果上一轮是**提权**运行、留下了 hosts 托管块，而这次 `__recover` 不是管理员，
    它清不掉 hosts，只能在日志里明确写一条警告；下一次以管理员身份启动的通途会在接管前清掉它。
- **自己验证一遍**：`.\tools\crash-test.ps1` 会快照当前网络设置 → 启动 → `taskkill /F` 强杀主进程 →
  断言系统代理 / hosts / guard.json / 残留进程都在规定时间内清理干净 → 打印检查表并还原快照。
  它还会区分「环境限制」与「代码问题」（前者会看到 `guard.log` 里提到作业对象）。
- **状态文件**：接管前的系统代理原值存在 `%APPDATA%\tongtu\sysproxy.json`，hosts 的托管块有明确的
  起止标记；还原即"按文件里的原值写回"和"移除托管块"。
- **状态文件原子写 + 损坏兜底**：`sysproxy.json` 用"临时文件 + 改名"写入，不会出现半截内容。
  万一它还是损坏了（断电正好撞上写入、磁盘满），启动 / 停止时会做**安全兜底**：如果系统代理此刻
  指向一个**没人监听的本地端口**（崩溃遗留的典型形态），就把代理关掉、让系统回到直连，并在日志里
  说明"原值已无法恢复"——而不是留下一个永远连不上的代理。端口上还有人在听（可能是你自己的
  Clash）或指向外部地址时，通途不猜、不动。
- **接管失败会回滚**：写注册表只有一部分成功时，立刻按刚抓到的原值回滚，不留半成品状态。
- **监护进程在接管之前就位**：改注册表 / 写 hosts 发生在启动流程里，监护进程提前拉起，
  连"刚启动就崩溃"这段窗口也有兜底。
- **hosts 残留会被点名**：上一轮提权运行时留下的托管块，如果这一轮没有管理员权限清理，
  启动摘要里会直接显示"Hosts 残留：需以管理员身份运行一次"，而不是让相关域名静默连不上。
- **不动你原有的「跳过代理」列表**：接管系统代理时，通途把 `localhost;127.0.0.1;::1;<local>`
  **合并**进你已有的 `ProxyOverride`（而不是整段替换），因此运行期间你配的内网绕过项
  （如 `192.168.*`、`10.*`、`*.corp.local`）照常生效；停止后再按 `sysproxy.json` 逐字还原。
- **被别人顶掉时不抢也不覆盖**：运行期间若有别的程序（Clash / v2rayN / 公司 VPN 客户端等）改写了系统代理，
  通途会把状态如实报成「系统代理：关（已被其他程序接管）」（窗口状态条、托盘 tooltip 与 `tongtu status` 同步），
  退出时**不动对方的设置**——只有当注册表里仍是我们写入的地址、且代理仍是开启状态时才按 `sysproxy.json` 还原。
  想重新拿回来：点一下托盘的「系统代理」开关即可（以当前值作为新的"原值"重新接管）。
- **端口被占用自动换口**：`listen` / `control` 被别的程序占住时不会启动失败——
  代理端口改用同主机的空闲端口（系统代理指向实际端口，对用户透明，摘要里显示的是实际端口）；
  控制端口同样换端口并**写回 `config.yaml`**（否则 `tongtu status` / `stop` 会找不到这个实例）。
  两种情况都会留一条 WARN 日志。控制端口的"这是别人"判断只对**确实是别的 HTTP 服务**生效：
  端口被非 HTTP 程序占住时，为安全起见仍按「tongtu 已在运行」处理，避免误起第二个实例。
- **hosts 刷新失败会短周期重试**：默认周期 10 分钟（`hosts_refresh_minutes`），某轮失败
  （DoH 抖动、hosts 被安全软件锁住等）后改为每分钟重试，成功再回到正常节奏——
  不让一次抖动导致托管块陈旧一整个周期。
- **遗留清理先确认"没人管了"**：清理（启动兜底与 `tongtu stop` 的兜底分支）之前先看两件事——
  状态文件里记的代理地址是否还连得上（还连得上就说明那轮接管的进程仍在跑，代理端口是它开的），
  以及 `guard.json` 里的主进程是否还活着。任一成立就整轮跳过：否则会把**另一个实例**正在用的
  系统代理静默清掉，而对方界面照旧显示「已启用」。多实例（换了控制端口/配置文件）时尤其重要。
  - 残留的窄情形：对方**只接管了 hosts**（系统代理没开），而 `guard.json` 已被本实例启动时覆盖。
    此时本轮的兜底清理可能短暂移除对方的托管块；对方会在下一次状态刷新（数秒内）自行补回，
    属自愈，不会造成持续影响。两个实例同时接管同一份系统状态本身就是互相覆盖，不做进一步协调。
- **hosts 原子写入**：先写同目录临时文件再改名覆盖，避免"清空后还没写完就被强杀"导致 hosts 被截断。
- 监护进程只在**确实接管了系统状态**时才会存在（托盘里手动打开开关时也会自动补上），
  不接管时不会多一个进程。

因此：**不运行时不会残留任何接管状态**；进程退出后不占用 CPU/内存（监护进程完成还原后自行退出）。

## 卸载

通途是绿色单文件，但它在系统里留下过自启、证书、RunOnce 与接管状态，建议按顺序撤销，
而不是只把 exe 拖进回收站——否则可能出现「开机时冒出一个报错」或「浏览器还指着一个不存在的代理」。
仓库自带脚本把这些步骤按顺序做完，并逐条报告结果：

```powershell
.\tools\uninstall.ps1                    # 停实例 + 撤销自启、证书、RunOnce、代理/hosts 残留（保留 exe 与配置）
.\tools\uninstall.ps1 -Purge             # 连 %APPDATA%\tongtu（配置 / 证书 / 日志）一起删
.\tools\uninstall.ps1 -Purge -RemoveExe  # 彻底删除
```

- 默认**不删** exe 与配置：误删配置的代价比多点一次高。
- 证书装在「当前用户」存储，撤销不需要管理员；只有清 hosts 托管块需要管理员，权限不够时脚本会点明该怎么做。
- `-KeepCert` 可保留本地根证书（例如你还要用别的工具复用同一套 CA）。
- 手工卸载的顺序与每一步在做什么，见 [USAGE.md 的「卸载」](USAGE.md#卸载)。

## 已知限制

- **github.com 主站可能被限速**：这是网络层速率限制，非代理问题；可达性由无 SNI 反代保证。
- **个别域名的干净 DoH 答案不可达**：例如 `www` / `help.steamcommunity.com` 会解析到国内打不通的机房，
  这类域名由 `dns.static_hosts` 的实测兜底 IP 兜住；如果你的线路也打不通，换成自己实测可用的 IP 即可。
- **1.1.1.1 / 8.8.8.8 在境内通常不可达**：仅作后备；本工具有端点熔断，失败端点会在冷却期内被跳过。
- **SNI 封锁是间歇性的**：网络窗口可能变化，工具会按 DNS 污染/封锁情况自动选择候选 IP。
- **QUIC / HTTP-3（UDP:443）不在加速范围内**：系统代理与 hosts 都只覆盖 TCP。反代路径已剥离
  上游的 `Alt-Svc`，避免浏览器去试注定失败的 QUIC；但浏览器仍可能对少数站点自行尝试 HTTP/3
  （表现为首次加载多几秒后回退 TCP），如需彻底关闭请在浏览器里停用 QUIC。
- Hosts 模式写入系统 hosts、绑定 `:443`/`:80` 需要管理员（低端口绑定本身非管理员也可，但写 hosts 必须管理员）。
- **hosts 模式里的「指向优选 IP」条目只写 IPv4**：反代域名会连 `::1` 一起写（本地 `[::1]` 监听就绪时），
  IPv6 优先的程序也会被本地接管；但「指向某个优选 IP」的条目没有干净的 AAAA 来源可校验（DoH 只取 A 记录），
  而写进 hosts 的地址会成为客户端**首选**（IPv6 优先），写错比不写更糟，因此保持不变。
  若某域名**只有 AAAA 记录**，它在这条路径上不会被加速；系统代理路径仍然可用——DoH 全部失败时会回退系统解析
  （`ip`，含 IPv6），由本机 IPv6 直连。

## 故障排查

- **curl 报 `CRYPT_E_NO_REVOCATION_CHECK`**：schannel 对本地 CA 无吊销点。加 `--ssl-no-revoke`（浏览器与 Steam 客户端无此问题）。
- **某个站点失败**：`tongtu test <域名>` 一行就能看出卡在哪：`解析IP(干净)` 是否被污染、
  `TCP:443` 是否可达、`直连HTTPS`（真 SNI）是否被阻断、`经代理` 是否正常、`无SNI反代`（✓/–）有没有命中。
  典型结论：
  - 直连失败 + 经代理成功 + 反代为 ✓ → 正常，就是这个域名必须走反代；
  - 直连失败 + 经代理也失败 + 反代为 – → 该域名也需要反代，把它加进 `mitm.domains`（注意逐个验证，
    别用 `*.steampowered.com` 这种通配）；
  - TCP:443 不可达 → 候选 IP 不可用，加入 `dns.static_hosts` 固定一个实测可用的 IP。
- **改坏了配置**：删除/改名 `config.yaml`，下次启动会按默认重建；历史版本在 `config.yaml.vN.bak`。
- **状态显示「系统代理：关（已被其他程序接管）」**：说明运行期间有别的程序改写了系统代理（Clash / v2rayN /
  公司 VPN 客户端等）。此时通途的代理其实已经不在生效路径上，并且**退出时不会覆盖对方的设置**。
  要么关掉那个程序，要么点一下托盘的「系统代理」开关把接管拿回来（会以当前值作为新的"原值"）。
- **日志里出现「端口被占用，已改用空闲端口」**：`listen` / `control` 被别的程序占住了，通途自动换到了空闲端口
  并继续运行（控制端口的新值会写回 `config.yaml`，所以 `tongtu status` / `stop` 照常可用）。
  若想让端口固定下来，改 `config.yaml` 里的 `listen` / `control` 即可。
- **双击后没看到窗口？** 窗口可能在屏幕边缘（位置被记住了，删掉 `%APPDATA%\tongtu\window.json` 即恢复默认），
  也可能启动失败：图形子系统下没有终端，失败信息会以**系统对话框**弹出，
  同时默认就有一份文件日志在 `%APPDATA%\tongtu\tongtu.log`（窗口里「日志 ▾ → 打开日志文件」可直接定位）。
- **关掉终端后进程还在？** 这是**预期行为**：界面就绪后通途会主动脱离控制台，避免"关终端＝被杀进程"。
  要退出请用托盘右键「退出」或 `tongtu stop`。
- **怎么确认没有残留？** 检查 `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings` 的
  `ProxyEnable` 是否为 `0`、hosts 里是否还有 `tongtu managed block` 标记，以及
  `%APPDATA%\tongtu` 下是否还有 `sysproxy.json` / `guard.json`。有残留时执行一次 `tongtu stop` 即可清理。
